# flow_push.js 部署与排错

成品油驾驶舱「前一日车流 / 单加」的每日自动更新脚本（WPS AirScript）。

---

## 一、它解决什么

驾驶舱「日销量走势」里每张站点卡的最后三行：

```
车流 883 车次
● 汽油 510 车次 · 34.94 升/次
● 柴油 373 车次 · 302.29 升/次
```

这些数字原先要人工从 15 个非油 V1 报表里抄，**一天不抄就停在旧日期**。
本脚本让它在金山文档云端每天自动跑，不再需要本机开机。

**为什么不能靠现有的 read_daily.js**：那份读的是「202611销售及库存日报（新).xlsx」的销售日报子表，
全簿 62 张子表都没有「车次」字段。车次只在 15 个非油 V1 报表的「今日填报」C/E 列。

**为什么 AirScript 反而能读**：脚本编辑器可以添加「云文档API」服务，用
`KSDrive.openFile(url)` 打开**同账号下的其他文档**（不是只能读当前文档）。

---

## 二、部署（8 步）

### 1. 打开承载文档
金山文档打开 **「非油销售汇总驾驶舱V1.xlsx」**（就是现有主脚本所在的那份）。

### 2. 进脚本编辑器
顶部菜单 **效率 → 高级开发 → 脚本编辑器**。

### 3. 新建脚本
左侧「脚本」栏 → 新建，命名 `flow_push`（或任意）。
**不要动**现有的 `cockpit_refresh_full_v3_6` —— 本脚本是独立的，互不影响。

### 4. 粘贴代码
把 `flow_push.js` **全选内容**粘贴进去。粘贴后先别急着跑，看第 5、6 步。

### 5. 添加两个服务（缺一不可）
脚本编辑器左侧 **「服务」** 面板：

| 服务 | 用途 | 不加会怎样 |
|---|---|---|
| **云文档API** | `KSDrive.openFile` 跨文档读表 | 报 `KSDrive is not defined` |
| **网络API** | `HTTP.fetch` 推送 GitHub | 报 `HTTP is not defined` |

### 6. 填 GitHub 令牌
代码顶部：

```js
TOKEN : '',   // ← 填在这里
```

填一个 **有 repo 权限的 PAT**（`ghp_` 开头）。可以直接复用现有主脚本里那个
（在 `cockpit_refresh_full_v3_6` 的 `CHART_GH_TOKEN` 常量里，同一串即可）。

> ⚠️ 令牌属于敏感信息。代码里的 `TOKEN` 只存在于云端脚本，**不要把填了令牌的文件外发或提交到 Git 仓库**。

### 7. 先干跑
保持 `PUSH : false`，点「运行」。控制台应打印：

```
===== 前一日车流推送 START ...
读取完成：15/15 站有数据
选定会计日 asof=2026-10-28（覆盖 15 站）
15 对加总：总车次 7223（汽 4669 / 柴 2554）
单数统计：总车次 7223（汽 4669 / 柴 2554）
差值：总 0 / 汽 0 / 柴 0  ✅ 吻合
【干跑】CFG.PUSH=false，不推送。
```

**核对要点**：
- 「读取完成」必须是 **15/15**。少站说明哪个文件没分享给本账号，看日志里的 `⚠️ 读取失败 <链接>`。
- 「差值」三项都应为 **0**（允许 ±2 的显示取整）。差得多说明「单数统计」还没刷到这一天，等主脚本 08:30/09:00 跑完再来一次即可。

### 8. 打开推送 + 定时任务
- 把 `PUSH : false` 改成 `PUSH : true`，**保存**。
- 菜单 **效率 → 高级开发 → 定时任务** → 新建：
  - 执行脚本：`flow_push`
  - 执行函数：`main`
  - 频率：**每天 09:40**

> 为什么是 09:40：主脚本 `cockpit_refresh_full_v3_6` 在 08:30 / 09:00 刷新驾驶舱和「单数统计」。
> 本脚本排在其后，才能拿到已刷新的公司级数字做对账。

## 三、跑通后的表现

脚本 PUT 成功后，GitHub 仓库 `lvritiann/youpin-sales-cockpit` 会新增/更新
`_incoming/flow.json`，自动触发 `rebuild-cockpit` 工作流：

```
应用最新日报数据      ← 销量/金额
应用最新车流数据      ← 车流（本脚本推的）
重建驾驶舱
发布到站点根目录
```

页面上的车流日期随之推进，无需人工。

**没收到 flow.json 时**（比如某天 AirScript 失败），工作流会打印
「未收到 _incoming/flow.json —— 沿用现有快照」，页面照常出，只是车流停在旧日期 —— 不会白屏。

## 四、排错

### ⓪ 运行结果一片空白，只有「初始化 / 已开始执行 / 执行完毕」三行通知（★ 最先查这条）
**耗时约 100ms、一行输出都没有 = 脚本根本没执行到 `main()`。**

原因：AirScript 2.0 的「运行」按钮**只执行顶层代码**，不会主动去找 `main` 函数来调用。
只写 `function main() { ... }` 而不在文件末尾调一次，就是静默空跑。

对照证据（2026-10-29 实测）：

| 脚本 | 末尾有没有 `main();` | 运行表现 |
|---|---|---|
| `read_daily.js`（销量链路，一直正常） | 第 581 行有 | 正常出日志 |
| `flow_push.js` 最初版本 | **没有** | 100ms 空白 |

修法：确认文件最末一行是 `main();`（紧跟在 `function main(){...}` 的收尾 `}` 之后，**顶层缩进 0**）。

自检技巧 —— 把下面 3 行单独跑一次：

```js
console.log('PROBE-A 顶层代码已执行 ' + new Date());
function main() { console.log('PROBE-B main 被调用'); }
main();
```

- 三行都出 → 环境正常，问题在日志筛选或粘贴没进编辑器
- 只出 PROBE-A → 说明「运行」确实不调 `main()`，末尾那句 `main();` 不能少
- **一行都不出** → 跑的不是这份代码：检查编辑器顶部的未保存标记（必须先点保存）、确认左侧文件树选中了哪个脚本（同一文档里还有 `cockpit_refresh_full_v3_6`，很容易跑错）

> 底部日志面板是**分级筛选**的（通知 / 信息 / 错误）。`console.log` 属「信息」级，
> 只勾「通知」会把它整层藏掉 —— 看起来就像脚本没跑。

### ① 所有站都「读取失败」
**九成是文件没分享给脚本运行账号。**
逐个确认 15 个 V1 报表对当前登录账号是「可阅读」以上权限。
脚本只能打开**当前登录用户有权限**的文档。

### ② 报 `KSDrive is not defined`
「服务」面板没加 **云文档API**。加上后重新保存再跑。

### ③ 报 `HTTP is not defined`
「服务」面板没加 **网络API**。

### ④ 读取成功但「选定会计日」是很久以前
有两种可能：
- **各站真的没填报** —— 去非油 V1「今日填报」看最近几天，如果全 0 就是没填；
- **`MIN_COVER` 阈值太高** —— 默认要求 ≥12 站同日有车次才认这天。某天只填了 8 站时，
  脚本会自动往前找最近一个够 15 站的日子。想放宽就把顶部 `MIN_COVER` 改成 8。

### ⑤ 「差值」偏差很大
「单数统计」表还是旧的。等主脚本 08:30/09:00 那两档跑完再手动运行一次。
若长期偏差，检查主脚本 `cockpit_refresh_full_v3_6` 是否正常。

### ⑥ 推送返回 401
令牌无效或过期。重新生成 PAT（勾 `repo` 权限），更新 `TOKEN`。

### ⑦ 推送返回 404
仓库名或路径写错。默认是
`lvritiann / youpin-sales-cockpit / _incoming/flow.json`，检查 `CFG` 里的 `OWNER / REPO / PATH`。

### ⑧ 推送成功但页面没更新
去 GitHub → Actions 看 `rebuild-cockpit` 有没有触发。没触发就手动 `Run workflow`。
触发但失败，看「应用最新车流数据」那一步的日志。

### ⑨ 想把某天的车流改回上一版
GitHub 上把 `_incoming/flow.json` 恢复成历史版本（Revert this commit），
Actions 会自动重建，页面回到那一天的车流。

## 五、口径（改代码前必读）

| 项 | 规则 |
|---|---|
| 数据来源 | 15 个非油 V1 报表 → `今日填报` 子表 → `A1:T731` |
| 列位 | A 日期 · B 区域南/东或北/西 · **C 柴油单数 · D 柴油升数 · E 汽油单数 · F 汽油升数** |
| 行号 | `row = 1 + 2 × (日期 − 2025-12-26)`；同一天占两行（南/东 + 北/西） |
| 「对」的合计 | 一对 = 两行相加（如华山 = 华山南 + 华山北） |
| 单加 | `该油品升数 ÷ 该油品车次`，**不是各站单加的算术平均** |
| 零值 | 车次为 0 视为未填报，**跳过，绝不补零** |
| 小额配送 | 公司级虚拟实体，无车流数据，不参与 |

## 六、回滚

本脚本完全独立，**删掉定时任务 / 删掉脚本即可停用**，
主脚本 `cockpit_refresh_full_v3_6` 与驾驶舱刷新不受任何影响。

停用后驾驶舱会沿用 `_incoming/flow.json` 里最后一次成功的快照，
需要回到人工维护时，改 `_kdocs/_flow_raw.json` 后跑 `python _kdocs/flow_sync.py`。
