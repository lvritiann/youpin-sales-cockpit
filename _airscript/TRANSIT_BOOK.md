> 2026-10-29 建。把「历史归档」从填报簿里搬出来，独立成一本在线工作簿。
> 对应脚本：`transit_sync.js`（挂中转簿）、`read_daily.js v2.9`（挂填报簿，已停写归档）

## 一、为什么要拆

填报簿「销售及库存日报」现在 **13.4 MB / 62 张子表**。拆之前先看清体积到底在谁身上：

| 分块 | 体积 | 占比 | 处置 |
|---|---:|---:|---|
| 渠道 / 结算分表（28 张） | 54.87 MB | 68.3% | **不动**（每天填报要写） |
| 核心台账（4 张） | 14.57 MB | 18.1% | **不动** |
| 15 站销售分表 | 8.35 MB | 10.4% | **不动** |
| 15 站库存分表 | 2.57 MB | 3.2% | **不动** |
| 「销售日报」子表本身 | 3.62 MB | **4.5%** | **不动** |

**结论：该拆的不是「销售日报」**（拆了只省 4.5%，却要改所有站的填报习惯）。
真正该搬走的是**只读的历史** —— 累计 1001 行站级明细 + 34 行月汇总，
它们和每日填报挤在同一本簿里，每次打开/另存都要一起搬运，月底清表时还有误删风险。

另外还有一个驾驶舱侧的硬需求：现在只有「月汇总 + 月站级」，
**做不出「任意区间 × 任意站」的切片**。中转簿补了 30,502 行 `date × station` 日粒度矩阵。

## 二、中转簿长什么样（6 张表）

| 表 | 行 × 列 | 内容 |
|---|---:|---|
| 说明 | 30 × 2 | 版式、口径铁律、自检基准、分工 |
| 月汇总 | 34 × 12 | 会计月一行：零售/柴油/汽油/小额/全口径/金额/站数/天数 |
| 站级明细 | 1,001 × 9 | 会计月 × 站（不含小额，小额是公司级，见月汇总独立列） |
| 日粒度 | 30,502 × **19** | **date × station 全矩阵**，2023-12-26 ~ 2026-10-25。含四段（-10#/0#/92#/95#）与柴汽各自升/金额 |
| 配置 | 13 × 3 | 填报簿 URL、会计月、令牌、开关 |
| 运行日志 | 表头 | 每跑一次追加一行 |

### 关键口径

```
会计月 = 每月 26 日 → 次月 25 日，标签取「止月」
        202610 = 2026-09-26 ~ 2026-10-25

全口径 = 零售（站行之和） + 小额配送（公司级虚拟实体，单独成行）
         日粒度里小额那一行：站名 = 「小额配送」，路段 = 「公司级」
```

### 自检基准（任何重建都必须回到这组数）

| 指标 | 数值 |
|---|---:|
| 零售合计 | 332,660.0 吨 |
| 柴油 | 142,110.4 吨 |
| 汽油 | 190,549.6 吨 |
| 小额 | 51,102.9 吨 |
| 全口径 | 383,762.8 吨 |
| 含税金额 | 301,375.3 万元 |

> 差 0.1 吨以上就要查。差异来源只允许是逐行四舍五入（实测三表相差 ≤ 0.03 吨）。

### ⚠️ 建簿时修掉的一个口径 bug

`gen_archive_tsv.py` 原写法：

```python
xt = r2(mc.get('m_xiao')) or r2(rec.get('xiao'))   # ❌ 混口径
```

`mc` 是「月销售累计」表的月值，`rec` 是「销售日报」日块累加值。于是同一张表里
**零售走日块、小额走月累计**，两套口径拼在一起，小额整体差 **2,358.53 吨**
（48,744.33 vs 51,102.86）。已改为只走日块：

```python
xt = r2(rec.get('xiao'))                            # ✅ 同源同口径
```

这条和「金额禁用月累计·小额行」是同一条铁律：那列含批发，会虚高到 1.55 亿，
日块实测只有 1.44 亿。**吨量也不例外。**

## 三、上传（一次性，约 30 秒）

文件已生成：`D:\高速延长公司综合管理平台\_publish\成品油经营数据中转簿.xlsx`（3.52 MB）

> **为什么必须手动上传一次？**
> 30,502 行 × 19 列 = 58 万格。走逐格 API 写入既不现实也不可靠；
> 上传 xlsx 是一次性把结构 + 数据 + 格式全部落地，保真度最高。

1. 打开 [WPS 云文档](https://www.kdocs.cn) → 进入「我的云文档」
2. 点「上传」→ 选上面那个 xlsx → 等它转成在线表格
3. 打开它，确认左下角有 **6 个页签**：说明 / 月汇总 / 站级明细 / 日粒度 / 配置 / 运行日志
4. 点右上「分享」→ 复制链接（形如 `https://www.kdocs.cn/l/xxxxx`）
5. 把这个链接填到 **「配置」表 → 第 2 行 → B 列**（键 = `填报簿URL`）——
   ⚠️ 注意这里填的是**填报簿**的链接，不是中转簿自己的

> 确认数据对不对：切到「月汇总」，A 列应该有 `2024-01` 到 `2026-10` 共 34 行；
> 最后一行 `2026-10` 的零售吨应是 `11864.76`。

## 五、两个脚本的分工

| | 填报簿 `read_daily.js` | 中转簿 `transit_sync.js` |
|---|---|---|
| 宿主 | 销售及库存日报 | 成品油经营数据中转簿 |
| 读 | 本簿本地读（销售日报 + 渠道 + 大客户明细，共 4,685 行） | 跨文档读填报簿「销售日报」 |
| 写 | 推 GitHub `_incoming/data.json` | 写本簿日粒度 / 站级明细 / 月汇总 / 日志 |
| 覆盖业务 | 全量：量 + 渠道 + 大客户 + 车流 + 单车加注 | **只有「量」** |
| 出错影响 | 驾驶舱不更新 | 中转簿不落表（驾驶舱照常） |

**为什么脚本不跟着搬到中转簿**：主脚本要读三张大表，读源留本地是零跨文档成本；
跨文档「写」在 WPS 上没验证过，不做没把握的事。反过来 `transit_sync.js`
跨文档只**读**（`flow_push.js` 已验证可行），写的是自己簿的表（本地写，已验证多年）。

**为什么不是把主脚本挂中转簿**：那样每次都要跨文档拉 4,685 行 × 大面积区域，
慢且容易踩内存；而且填报簿就不能改名/另存了（一改就要动脚本）。

## 六、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `KSDrive 未定义` | 没加「云文档API」服务 | 脚本编辑器左侧「服务」→ 添加 |
| `「配置」表 A2 没填` | 配置表 B2 空 | 填填报簿的分享链接 |
| `openFile 返回空` / `读填报簿失败` | 链接填成了浏览器地址栏 URL；或填报簿改名/另存后分享失效；或账号无权限 | 重新「分享」一次拿新链接 |
| `填报簿里找不到「销售日报」` | 子表被改名 | 改「配置」表的「日报表名」 |
| 日粒度行数暴涨（重复行） | 去重索引没建起来 | 检查 A 列日期是否被 WPS 自动转成了日期格式（应是 `2026-10-26` 文本）；`CFG.DAY_ROWS` 是否被调小 |
| 月汇总「小额吨」比预期大 | 又混了月累计口径 | 见 §二 的口径 bug 说明 |
| 站级明细「升」列全空 | 正常 | 归档口径本身没有逐站加注升数，留空不造数 |
| 每天 26 号后数据不进来 | 会计月已翻月，填报簿还没填新月份 | 正常，等填报簿 26 号起填新数据 |

### 重跑是否安全

安全。三个 upsert 的键：
- 日粒度 = `日期 + 站名`
- 站级明细 = `会计月 + 站名`
- 月汇总 = `会计月`

跑 10 次和跑 1 次结果完全一样。

## 七、本地重建中转簿

数据源变了（比如补了某个月的历史）之后重跑这三步：

```bash
cd D:\高速延长公司综合管理平台\_kdocs

# 1) 扫日粒度矩阵（34 个日报 → 30,502 行）
python scan_daymatrix.py

# 2) 生成月汇总 / 站级明细 TSV（会与第 1 步交叉自检）
python gen_archive_tsv.py

# 3) 合成 xlsx
python build_transit_book.py
```

每一步都会打印自检结果。第 2 步必须看到：

```
✅ 自检通过：34 个月的零售吨与小额吨都与 folder_scan 日块口径完全一致
```

否则不要上传 —— 说明口径又漂了。

| 脚本 | 作用 |
|---|---|
| `scan_daymatrix.py` | 逐日 × 逐站矩阵 → `_archive/daymatrix.tsv` |
| `gen_archive_tsv.py` | 月汇总 + 站级明细 → `_archive/中转表_*.tsv` |
| `build_transit_book.py` | 三个 TSV → `_publish/成品油经营数据中转簿.xlsx` |
